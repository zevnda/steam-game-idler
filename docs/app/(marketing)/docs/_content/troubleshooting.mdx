# Troubleshooting

This page covers common issues and their solutions when using Steam Game Idler.

<Callout type="info">
    Always check the [FAQ](/docs/faq) section first, as many common questions are answered there
</Callout>

## Preliminary Checks

<Steps>
  <Step>
    ### Check System Requirements
    - Windows 10/11 or Linux (64-bit)
    - Internet connection
    - Steam client installed and running (only required if you use [Legacy Sign-in](/docs/get-started/how-to-sign-in#legacy-sign-in), which is Windows-only — Linux supports Steam Sign-in only)
  </Step>

  <Step>
    ### Verify Your Sign-In
    - If using [Steam Sign-in](/docs/get-started/how-to-sign-in#steam-sign-in), make sure you completed any Steam Guard prompt fully
    - If using [Legacy Sign-in](/docs/get-started/how-to-sign-in#legacy-sign-in), make sure the Steam client is running and you're signed in to at least one account
    - Your Steam profile is set to public (required for some features regardless of sign-in method)
  </Step>

  <Step>
    ### Check SGI Installation
    - SGI is installed in the default location
    - You're running the latest version
    - Windows Defender/antivirus isn't blocking SGI
  </Step>
</Steps>

## Installation Issues

<Accordions type="multiple">
  <Accordion title="SGI won't install" id="install-fails">
    - Make sure you downloaded the installer from the official [GitHub releases page](https://github.com/zevnda/steam-game-idler/releases) or [steamgameidler.com](https://steamgameidler.com). Files from other sources may be incomplete or modified
    - Right-click the installer and select **Run as administrator**
    - Temporarily disable your antivirus/Windows Defender during installation (see below), then re-enable it afterwards
    - Make sure you have enough free disk space
    - If the installer hangs or crashes, restart your PC and try again
  </Accordion>

  <Accordion title="Antivirus or Windows Defender is blocking SGI" id="antivirus-blocking">
    SGI's installer and its bundled helper process (`SteamUtility.exe`, used for idling, achievement management, and Steam Sign-in) are not code-signed with a paid certificate, so Windows SmartScreen and some antivirus programs may flag them as "unknown publisher" or quarantine them. This is a false positive.

    If a feature fails immediately with **"The Steam agent component is missing from this installation."** or **"Couldn't start the Steam agent process."**, `SteamUtility.exe` has most likely been quarantined or deleted — follow the steps below.

    <Steps>
      <Step>
        ### If SmartScreen blocks the installer
        Click **More info**, then **Run anyway**
      </Step>

      <Step>
        ### If your antivirus quarantines or deletes a file
        Restore the file from quarantine, then add an exclusion for SGI's install folder (default: `C:\Program Files\Steam Game Idler\`) and for `%appdata%\com.zevnda.steam-game-idler\`
      </Step>

      <Step>
        ### If a feature won't start because SteamUtility.exe is removed
        Re-run the installer to restore the missing file, after adding the exclusion above
      </Step>
    </Steps>

    <Callout type="info">
      If you'd like to verify the source code yourself, SGI's source code is entirely public. See the [GitHub repository](https://github.com/zevnda/steam-game-idler)
    </Callout>
  </Accordion>

  <Accordion title="Missing .NET Framework / SteamUtility errors" id="dotnet-missing">
    SGI's idling, sign-in, and achievement features rely on a bundled helper process (`SteamUtility.exe`) which requires the **.NET Framework 4.8** runtime. Most Windows 10/11 installs already include this, but if idling, sign-in, or achievement actions fail immediately with no clear error:

    - Install the [.NET Framework 4.8 runtime](https://dotnet.microsoft.com/en-us/download/dotnet-framework/net48) from Microsoft
    - Restart your PC after installing, then try again

    This is also a common cause of **"The Steam agent process closed unexpectedly."** or **"Steam took too long to respond. Please try again."** — both mean `SteamUtility.exe` stopped responding, which a missing runtime causes just as often as the antivirus case above.
  </Accordion>

  <Accordion title="I need admin rights to install or update SGI" id="admin-rights">
    SGI installs per-machine by default (available to all Windows users on the PC), which requires administrator privileges. If you don't have admin rights:

    - Ask an administrator to run the installer once
    - Updates are installed silently in the background and also require the original install permissions. If updates consistently fail, reinstall with an administrator account
  </Accordion>
</Accordions>

## Startup Issues

<Accordions type="multiple">
  <Accordion title="SGI won't start/run at all" id="wont-start">
    <Steps>
      <Step>
        ### Check for a hidden window or tray icon
        SGI's main window is hidden until it finishes loading, and may also be set to start minimized. Look for the SGI icon in your system tray (bottom-right of the taskbar, click the **^** arrow to see hidden icons)
      </Step>

      <Step>
        ### Check for leftover processes
        Open **Task Manager** and look for `steam-game-idler.exe` and `SteamUtility.exe`. If either is running but nothing appears, end both processes and relaunch SGI
      </Step>

      <Step>
        ### Check the log file
        If SGI ran before, open today's log file from <MockButton type='view-log-file' /> in [Debug Settings](/docs/settings/debug) and check it for errors from the last session
      </Step>

      <Step>
        ### Reset window state
        A corrupted window-position file can prevent the window from appearing. Close SGI completely (including via Task Manager), then delete `%appdata%\com.zevnda.steam-game-idler\.window-state.json` (if present) and relaunch
      </Step>

      <Step>
        ### Reinstall
        If none of the above works, uninstall SGI, restart your PC, and reinstall the latest version
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="SGI is open in the system tray but I can't see the main window" id="tray-no-window">
    This usually means **Start minimized to tray** is enabled, or the window was closed to tray and is simply hidden.

    - **Left-click** the SGI icon in the system tray to show and focus the main window
    - If clicking the tray icon does nothing, right-click it and select **Show**
    - If the window still doesn't appear, it may be positioned off-screen (see below)
    - To stop SGI from starting minimized, go to <MockButton type='context-cog' content='Settings → General' /> and disable **Start minimized**
    - Can also happen if **WebView2** is missing or outdated. Download the "Evergreen Bootstrapper" via [Microsoft's WebView2 download page](https://developer.microsoft.com/en-us/microsoft-edge/webview2/) and relaunch SGI
  </Accordion>

  <Accordion title="The window appears off-screen, too small, or in the wrong position" id="window-offscreen">
    SGI remembers its window size and position between sessions. If you changed monitor setups (e.g. disconnected a second monitor) the window may open off-screen.

    - Try pressing **Win + Shift + Left/Right Arrow** while the window is focused (use Alt+Tab to focus it) to move it back to your main display
    - Right-click the SGI taskbar icon and choose **Move** (or **Maximize**) if available
    - As a last resort, fully close SGI, delete `%appdata%\com.zevnda.steam-game-idler\.window-state.json`, and relaunch. This resets the window to its default size and position
  </Accordion>

  <Accordion title="SGI starts but crashes or closes immediately" id="crash-on-start">
    - Check the most recent log file (in the `logs` folder next to where SGI stores its settings, see [Debug Settings](/docs/settings/debug)) for the last recorded entries before the crash
    - Make sure your Windows is up to date. Tauri-based apps depend on the WebView2 runtime, which ships with Windows 10/11 but can be repaired via [Microsoft's WebView2 download page](https://developer.microsoft.com/en-us/microsoft-edge/webview2/) if missing or corrupted
    - If your settings file is corrupted, SGI may fail to start. Open the settings folder via <MockButton type='open-settings-file' /> in [Debug Settings](/docs/settings/debug) (or `%appdata%\com.zevnda.steam-game-idler\cache\` for an installed build) and rename or move `settings.json` elsewhere, then relaunch. SGI will recreate it with defaults
    - Try reinstalling the latest version
  </Accordion>
</Accordions>

## Sign-In Issues

<Accordions type="multiple">
  <Accordion title="'Steam Sign-in' fails or gets stuck" id="agent-signin-stuck">
    - Make sure you have an active internet connection
    - Double check your username and password. If you're not sure, try signing in on [steamcommunity.com](https://steamcommunity.com/) directly first
    - If using the QR code, make sure you scanned it with the **Steam** mobile app's own QR scanner (top-right icon), not a generic QR app, and approve the prompt on your phone
    - An unscanned QR code expires after a short time and will automatically refresh itself, so there's no need to reopen the sign-in screen
    - Close the sign-in window and try again. It can occasionally get stuck on a stale attempt

    What each on-screen error means:
    - **"Incorrect username or password."** — self-explanatory; Steam doesn't distinguish a wrong username from a wrong password, so double-check both
    - **"Sign-in request denied in the Steam Mobile app. Please try again."** — appears when **Deny** is tapped (instead of **Approve**) for either a QR sign-in or a 2FA confirmation prompt. This is never auto-retried since it reflects a deliberate choice — just sign in again and tap **Approve** this time
    - **"Your Steam session isn't active anymore. Please sign in again."** or **"Your Steam ID hasn't been resolved yet. Please try again in a moment."** — usually transient, right after signing in or if the account was signed in elsewhere (see the "Signed in on another device" reconnect prompt). Wait a moment and retry
  </Accordion>

  <Accordion title="No Steam accounts show up on the Legacy Sign-in screen" id="no-accounts">
    Legacy Sign-in reads your locally saved Steam logins to populate the account picker.

    - Make sure the Steam client is installed and that you've logged in to your account(s) through Steam at least once
    - Open Steam and sign in normally, then restart SGI
    - If you use **Steam Guard**, complete the login fully (don't cancel at the 2FA prompt) before switching to SGI
    - If you'd rather not deal with the local Steam client at all, use [Steam Sign-in](/docs/get-started/how-to-sign-in#steam-sign-in) instead

    - **"Couldn't find a local Steam installation."** means SGI couldn't locate Steam at all — confirm it's actually installed
    - **"Couldn't read this device's saved Steam accounts."** means SGI found Steam but couldn't read its `loginusers.vdf` file. Signing in through the Steam client at least once (as above) regenerates this file
  </Accordion>

  <Accordion title="Switching Legacy Sign-in accounts, or launching Steam from SGI, fails" id="legacy-account-switch-fails">
    These errors are all specific to **Legacy Sign-in**'s account switcher, which works by directly editing your local Steam client's saved login state:

    - **"That account could no longer be found."** — the account was removed from `loginusers.vdf` (e.g. it was signed out of the Steam client entirely) since SGI last read it. Sign in to it through Steam once more, then try switching again
    - **"Couldn't switch Steam accounts."** — SGI couldn't update the registry value Steam uses to decide which account to auto-login. Make sure Steam is fully closed before switching, and that SGI has normal write access to `HKEY_CURRENT_USER` (try running SGI as administrator once if this persists)
    - **"Couldn't start the Steam client."** — SGI couldn't launch `steam.exe`. Make sure Steam is installed in a standard location and isn't itself broken (try launching it manually)
    - **"Couldn't load account details right now."** — a transient failure fetching that account's profile summary from Steam. Retry, or check your internet connection
  </Accordion>

  <Accordion title="A 'Steam is closed' warning appears while using SGI" id="steam-closed-warning">
    This only affects **Legacy Sign-in** accounts, which depend on the local Steam client staying open and signed in. If Steam closes, is restarted, or you sign out of it while SGI is running, any active idling/farming/unlocking for that account is stopped and this warning appears until Steam is running and signed in again.

    - Reopen the Steam client and make sure you're signed in to the same account
    - This doesn't affect [Steam Sign-in](/docs/get-started/how-to-sign-in#steam-sign-in) accounts, since they don't need a local Steam client at all

    You may also see this as **"Steam isn't running. Please start Steam and try again."** on a specific action (starting idling, unlocking an achievement, etc.) rather than as a standing banner — same cause, same fix.
  </Accordion>

  <Accordion title="Signed in, but my games list is empty or incomplete" id="empty-games-list">
    - Your Steam profile (or at least your **game details**) must be set to **Public** for SGI to read your library. Check this in your Steam profile's privacy settings
    - Try clicking <MockButton type='content' content='Refresh' /> on the <MockButton type='your-games' /> page
    - Try toggling **Settings → Debug → Clear Data** as a last resort if the cached games list is stuck (note this signs out every account and clears all local data)
  </Accordion>
</Accordions>

## Idling Issues

<Accordions type="multiple">
  <Accordion title="A game won't start idling" id="idle-wont-start">
    - If using **Legacy Sign-in**, make sure the Steam client is running and you're signed in to the same account you're using in SGI
    - Make sure the game is actually owned on this account. SGI can't idle games you don't own
    - Check the log file (<MockButton type='view-log-file' /> in [Debug Settings](/docs/settings/debug)) for a "Failed to start idling" message
    - If you recently reinstalled SGI, make sure `SteamUtility.exe` wasn't removed by your antivirus (see [Antivirus or Windows Defender is blocking SGI](#antivirus-blocking))
    - Close and reopen SGI, then try idling the game again

    If you see **"Couldn't start idling this game."**, this is the generic idle-start failure above — check the log file for the specific underlying reason (it's usually one of the causes listed here).
  </Accordion>

  <Accordion title="A game shows as idling in SGI but Steam doesn't show it as 'Currently in game'" id="idle-not-reflected">
    - Give it a minute, since there's a short delay before Steam's status updates
    - Make sure Steam itself is online (not in **Offline Mode**), as idling relies on Steam's servers being reachable
    - If using **Legacy Sign-in**, restarting Steam (not SGI) while a game is idling can desync the status. Stop and restart idling for that game
  </Accordion>

  <Accordion title="Idling stops by itself" id="idle-stops">
    - Make sure your PC isn't going to sleep. Adjust Windows power settings so it stays awake while idling
    - If using **Legacy Sign-in**, Steam will stop "in-game" status if you launch the same game manually, or if Steam restarts/updates in the background
    - Check the log file for errors around the time idling stopped
  </Accordion>

  <Accordion title="Leftover SteamUtility.exe processes after closing SGI or a crash" id="leftover-processes">
    If SGI is force-closed (e.g. via Task Manager, or a crash) before it can clean up, helper processes can be left running.

    - Open **Task Manager**, find any `SteamUtility.exe` entries, and select **End Task** for each
    - This won't affect your Steam library or achievements. It only stops the helper process
    - To avoid this in future, close SGI normally (via the tray menu **Quit** option) rather than force-closing it
  </Accordion>

  <Accordion title='"This game has already reached its max playtime cap"' id="max-playtime-cap-reached">
    This is expected, not a bug. It means a **max playtime** limit is configured for this game (or for all games) under [Settings → Game Settings](/docs/settings/game-settings), and the game's total recorded playtime has already reached it. This cap applies everywhere a game can be idled — manual and automatic idling, the Achievement Unlocker, and Card Farming.

    - Raise or remove the max playtime limit in <MockButton type='context-cog' content='Settings → Game Settings' /> if you want to keep idling this game
  </Accordion>
</Accordions>

## Free Games Issues

<Accordions type="multiple">
  <Accordion title={`"Couldn't check Steam for free games right now"`} id="free-games-scrape-fails">
    This means SGI couldn't fetch or parse Steam's current free-games listings, which usually means Steam's storefront is temporarily unreachable or changed in a way SGI's scraper doesn't recognize yet.

    - Check your internet connection and try again in a few minutes
    - If this keeps happening across multiple sessions, it's worth reporting as a bug — see [Getting Help](#getting-help)
  </Accordion>

  <Accordion title={`"Couldn't sign in/out of the Steam Store" (Gamer tier auto-redeem)`} id="free-games-store-signin-fails">
    Auto-redemption (Gamer tier) needs its own signed-in Steam Store session, separate from your SGI sign-in.

    - **"Couldn't sign in to the Steam Store. Please try again."** or **"Couldn't sign out of the Steam Store. Please try again."** — retry from <MockButton type='context-cog' content='Settings → Free Games' />. If it keeps failing, sign out and back in again to refresh the session
    - Manual claiming (the **Claim** button on the Free Games page) doesn't need this session and still works if auto-redeem is broken
  </Accordion>

  <Accordion title={`"Couldn't claim this game. It may no longer be free, or you may already own it"`} id="free-games-claim-fails">
    This isn't a bug — it means the claim itself was rejected by Steam, most commonly because:

    - The game stopped being free between SGI listing it and you clicking **Claim** (free-game promotions can end abruptly)
    - You already own the game on this account
    - Check your library to confirm — if the game is missing and still shows as free on Steam directly, try claiming again
  </Accordion>
</Accordions>

## Card Farming & Inventory Manager Issues

<Accordions type="multiple">
  <Accordion title='"Not logged in" or authentication errors' id="card-farming-not-logged-in">
    Card Farming and Inventory Manager rely on [Steam Credentials](/docs/steam-credentials), Steam Community session cookies which are separate from your SGI sign-in and expire periodically.

    - Go to **Settings → Steam Credentials** and re-authenticate (see the [Steam Credentials](/docs/steam-credentials) guide)
    - If you're on a **Gamer** tier account using **Steam Sign-in**, this normally happens automatically. Check that your subscription is still active
    - If you use **Family View** or have a **Steam Guard Mobile Authenticator**, make sure you complete the full login (these accounts often need the additional `steamMachineAuth` cookie)
    - Session cookies typically last a few hours to a few weeks. If farming worked before and suddenly stops with login errors, this is the most common cause

    On-screen error text and what it means:
    - **"Couldn't sign in to Steam Community. Check your cookies and try again."** — shown for a fresh cookie paste/connect attempt that didn't validate
    - **"Your Steam Community session has expired. Please reconnect to continue."** — shown when an already-working session stops working mid-farm/mid-session. Both point at the same fix above
  </Accordion>

  <Accordion title="Family View is restricting Card Farming or Inventory Manager" id="family-view-restricted">
    If you see **"Family View is enabled on your Steam account. Disable Family View and try again."**, this is a different problem from the session/cookie errors above — your session cookies are genuinely valid, but Steam's Family View PIN gate is blocking this content class regardless. Reconnecting or re-pasting cookies will not fix this.

    - Open the Steam client, go to your account menu, and disable **Family View** (you'll need the Family View PIN)
    - Once disabled, Card Farming and Inventory Manager work normally again with no need to reconnect
  </Accordion>

  <Accordion title="Card Farming isn't detecting card drops" id="card-farming-no-drops">
    - Make sure the games you're farming actually have **remaining card drops** for your account. Check your Badges page on Steam
    - Make sure your Steam profile's **game details/inventory** are set to Public
    - Re-authenticate if your session has expired (see above)
  </Accordion>

  <Accordion title="Listing cards on the Marketplace fails" id="market-listing-fails">
    - Make sure your Steam account doesn't have a **trade or market restriction** (new accounts, accounts without a phone number, or VAC-banned accounts can't use the Market)
    - Make sure you have **Steam Guard Mobile Authenticator** enabled for at least 7 days. Valve requires this for market access
    - If you're listing many items quickly, Steam may rate-limit you. Wait a few minutes and try again
    - Re-authenticate if your session cookies have expired
  </Accordion>

  <Accordion title="Inventory Manager can't load items, prices, or listings" id="inventory-lookup-fails">
    A few distinct Inventory Manager errors, all usually transient Steam-side issues rather than something wrong with your account:

    - **"Couldn't load your Steam Community inventory right now."** / **"Couldn't fetch a market price right now."** / **"Couldn't read your active market listings."** — Steam Community was unreachable or returned an unexpected response. Wait a moment and retry
    - **"Steam is rate-limiting price lookups right now. Please try again in a moment."** — you've fetched too many item prices in a short time. This is separate from the Marketplace's own listing rate limit (see [Listing cards on the Marketplace fails](#market-listing-fails)) — wait a few minutes before fetching more prices
    - **"That item couldn't be found in your cached inventory."** — your local inventory cache is out of sync with Steam (e.g. the item was traded/sold elsewhere since the last refresh). Refresh your inventory to resync
    - **"Couldn't read or write the inventory cache."** — a local disk read/write failure. See [My settings reset, or SGI behaves like a fresh install](#settings-reset) for the same underlying cache-file pattern
  </Accordion>
</Accordions>

## Achievement Manager & Unlocker Issues

<Accordions type="multiple">
  <Accordion title="Achievements list is empty or won't load" id="achievements-empty">
    - Make sure the game actually has achievements (some games genuinely have none — SGI shows **"This app doesn't have achievement data."** in this case, which is expected, not a bug)
    - Try toggling the **refresh/refetch** option for that game to force SGI to re-fetch the achievement schema from Steam
    - If using **Legacy Sign-in**, make sure the Steam client is running and online
  </Accordion>

  <Accordion title="Unlocking, locking, or toggling an achievement fails" id="achievement-toggle-fails">
    - If using **Legacy Sign-in**, make sure the Steam client is running and you're signed in to the matching account
    - Make sure the game isn't currently being idled by another tool, or already running through Steam itself, which can conflict with `SteamUtility.exe`
    - Check the log file for a specific error
    - Some games use **Family Sharing** or third-party anti-cheat that blocks stat writes. These games generally can't be modified

    On-screen error text and what it means:
    - **"That value is set by the game server and can't be changed."** — a genuinely different case from the Family Sharing one above. This achievement or statistic is flagged by the game itself as server-authoritative, so no client (SGI included) can write to it. This is a Steam-side restriction, not a bug
    - **"That achievement/statistic couldn't be found."** — usually a stale cached achievement schema. Try the refresh/refetch option above; if it still fails afterward, it's worth reporting
  </Accordion>

  <Accordion title='"This game isn’t supported for achievements when signed in with Steam"' id="achievement-game-coordinator-unsupported">
    This is expected, not a bug. A small set of games (Team Fortress 2, Dota 2, CS2, Left 4 Dead 2, Portal 2) use Valve's Game Coordinator system for stats, which isn't reachable through **Steam Sign-in**'s architecture at all.

    - **On Windows**: switch to [Legacy Sign-in](/docs/get-started/how-to-sign-in#legacy-sign-in) for these specific games, which has no such restriction
    - **On Linux**: there's no local-client fallback (Legacy Sign-in doesn't exist on Linux), so these games can't be managed at all — this is a Steam architecture limitation, not something SGI can work around
  </Accordion>

  <Accordion title="Achievement Unlocker isn't progressing" id="achievement-unlocker-stuck">
    - Make sure SGI is open (it can be minimized to tray, but not fully closed) for scheduled unlocking to continue
    - Check your unlock order, delay, and schedule settings under [Settings → Achievement Unlocker](/docs/settings/achievement-unlocker)
    - If you imported custom unlock timings, make sure the achievement names match exactly. See [Import Timings](/docs/features/achievement-unlocker/import-timings)
    - Check the log file for errors during the scheduled run
  </Accordion>

  <Accordion title="Import Timings fails" id="import-timings-fails">
    [Import Timings](/docs/features/achievement-unlocker/import-timings) fetches another Steam profile's real unlock timestamps for a game, so its errors are about that target profile, not your own account or sign-in:

    - **"That profile is private or has no public achievement data."** — the profile you entered needs its game details/achievements set to public. Try a different profile, or ask that player to make theirs public temporarily
    - **"That player has no achievements with unlock timestamps for this game."** — the profile is public, but hasn't unlocked any achievements for this specific game
    - **"Couldn't resolve that profile."** — the SteamID64, profile URL, or vanity URL you entered couldn't be matched to a Steam account. Double-check it's correct
  </Accordion>
</Accordions>

## Settings & Data Issues

<Accordions type="multiple">
  <Accordion title="My settings reset, or SGI behaves like a fresh install" id="settings-reset">
    SGI stores app-wide settings in one `settings.json`, plus a separate file per feature (Achievement Unlocker, Card Farming, Inventory Manager, Free Games) for each signed-in Steam account. If any of these files becomes corrupted or unreadable, SGI falls back to that file's defaults automatically rather than failing to start.

    - Click <MockButton type='open-settings-file' /> in [Debug Settings](/docs/settings/debug) to locate your settings folder
    - If you have a previously exported settings backup, re-import it (see [Export Settings](/docs/settings/debug#export-settings))
    - Switching accounts in SGI loads separate per-feature settings files for that account. This is expected, not a bug

    Any error mentioning it "couldn't read or write" a specific cache/settings file (games, favorites, automatic idler, achievement unlocker queue/settings/order, card farming, inventory manager, free games) follows this same self-healing pattern — SGI resets just that one file to defaults rather than failing to start.
  </Accordion>

  <Accordion title="Steam Web API key errors" id="api-key-errors">
    These appear when adding your own [Steam Web API key](https://steamcommunity.com/dev/apikey) override under <MockButton type='context-cog' content='Settings → General' />:

    - **"Steam rejected that API key. Double-check it and try again."** — the key itself is invalid. Generate a fresh one from Steam and re-paste it
    - **"Couldn't access the Windows Credential Manager to store your API key."** — SGI couldn't save the key to your OS's secure credential store. This can happen if the credential store service isn't running, or (on Linux) if no keyring is set up — see [Sign-in fails or 'Your Steam session isn't active anymore' error](#linux-keyring-secret-service) for the same underlying fix
  </Accordion>

  <Accordion title="Custom background image won't upload" id="background-image-invalid">
    **"That image couldn't be used - check the file type and size and try again."** means the file you picked under <MockButton type='context-cog' content='Settings → Customization' /> failed validation.

    - Use a standard image format (PNG, JPG/JPEG, or WebP)
    - Try a smaller file if it's a very large/high-resolution image
  </Accordion>

  <Accordion title="License key won't activate" id="license-key-activation-fails">
    **"Couldn't activate this license key. Check that it's correct and try again."** means Steam Game Idler's licensing server rejected the key you entered under <MockButton type='context-cog' content='Settings → Subscription' />.

    - Double-check you copied the entire key with no extra spaces
    - Make sure you have an active internet connection

    - If you're confident the key is correct and this persists, see [Getting Help](#getting-help)
  </Accordion>

## Update Issues

<Accordions type="multiple">
  <Accordion title='"Check for updates" does nothing, or no updates are found' id="update-check-nothing">
    - Make sure you have an active internet connection
    - SGI checks for updates via GitHub. If GitHub is unreachable from your network (e.g. blocked by a firewall/VPN), the check will fail silently
    - You can always download the latest release manually from the [GitHub releases page](https://github.com/zevnda/steam-game-idler/releases)
    - **Portable** builds don't support automatic updates. Download and replace the executable manually
  </Accordion>

  <Accordion title="Update downloads but SGI doesn't restart, or restarts into the old version" id="update-stuck">
    - Manually close SGI completely (including from the system tray and Task Manager), then reopen it
    - If the version number still hasn't changed, uninstall and reinstall using the latest installer from GitHub
  </Accordion>
</Accordions>

## General Performance Issues

<Accordions type="multiple">
  <Accordion title="SGI is using high CPU or memory" id="high-cpu-memory">
    - If using **Legacy Sign-in**, idling many games simultaneously spawns a separate helper process per game. This is normal, but idling a very large number of games at once will increase resource usage. **Steam Sign-in** accounts idle through one shared session instead, which uses noticeably less
    - Check **Task Manager** to confirm whether the usage comes from `steam-game-idler.exe`, `SteamUtility.exe` or `webview2.exe` processes
    - Update to the latest version, as performance fixes are released regularly. See the [Changelog](/changelog)
  </Accordion>

  <Accordion title="SGI feels slow or unresponsive" id="sgi-slow">
    - A large Steam library (thousands of games) can make initial loading slower. Give it a moment on first launch after sign-in
    - Running several **Steam Sign-in** accounts at once (see [Multi-Account](/docs/get-started/multi-account)) uses more memory and network than a single account. Reduce the number of concurrently signed-in accounts if resources are tight
    - Check the log file ([Debug Settings](/docs/settings/debug)) for repeated errors that may indicate a stuck background task
  </Accordion>
</Accordions>

## Linux-Specific Notes

<Accordions type="multiple">
  <Accordion title="Which Linux install format should I use?" id="linux-which-format">
    `.deb` and `.rpm` are recommended — they run under native Wayland and don't have the AppImage's performance caveat below, plus they support the desktop's normal application launcher integration. The trade-off is no in-app automatic updates (see [Install](/docs/get-started/install#linux) for the full comparison). Use the AppImage if you want automatic updates, or if your distro doesn't provide a compatible `.deb`/`.rpm`.
  </Accordion>

  <Accordion title="The AppImage feels slower or laggier than the .deb/.rpm install" id="linux-appimage-lag">
    This is expected, not a bug. The AppImage runs through a compatibility layer (XWayland) on a Wayland desktop, which has a real, hardware-independent performance cost. A `.deb`/`.rpm` install runs under native Wayland with no such layer. Switch to `.deb`/`.rpm` if this is noticeable for you.
  </Accordion>

  <Accordion title="A few visual quirks on Linux" id="linux-visual-quirks">
    A handful of small, cosmetic differences from Windows are known platform limitations, not bugs, and aren't fixable from SGI's side:
    - The window doesn't have rounded corners (Windows gets this from Windows 11's own window manager; Linux desktops have no equivalent for an undecorated window)
    - Left-clicking the tray icon always opens the tray menu instead of showing the window (a Linux tray-icon protocol limitation with no left/right-click distinction)
    - One extra click is sometimes needed after dragging the window by its titlebar (a currently-open upstream GTK issue)
    - An AppImage's taskbar/dock icon may show as generic instead of the SGI icon, even though the tray icon is correct — install via `.deb`/`.rpm` if this bothers you, since desktop icon integration is an AppImage ecosystem limitation, not something specific to SGI
  </Accordion>

  <Accordion title="Missing dependency errors on install" id="linux-missing-deps">
    A `.deb`/`.rpm` install pulls in its required system libraries (WebKitGTK, GTK, `libayatana-appindicator3`, `libsecret`) automatically via your package manager. If you see a missing-dependency error anyway, make sure your package manager's repositories are up to date (`sudo apt update` / `sudo dnf check-update`) and try reinstalling. The AppImage bundles most of what it needs, so this shouldn't affect it.
  </Accordion>

  <Accordion title="Sign-in fails or 'Your Steam session isn't active anymore' error" id="linux-keyring-secret-service">
    SGI securely saves your session using your OS's built-in keyring. If your Linux setup doesn't have one running or SGI can't access it, you will need to fix this on your system, since SGI can't install or unlock it for you.

    - **GNOME desktops** (Ubuntu, Fedora Workstation, etc.): usually works automatically. If not, install it and log back in:
      ```bash
      sudo apt install gnome-keyring   # Ubuntu/Debian
      sudo dnf install gnome-keyring   # Fedora
      ```
    - **KDE Plasma desktops** (Kubuntu, Fedora KDE, etc.): go to **System Settings → KDE Wallet** and enable **"Enable the KDE Wallet subsystem"**
    - **Minimal desktops/tiling window managers** (Sway, i3, Hyprland, etc.): install it, then set it to start with your session — check your window manager's documentation for how to autostart it
      ```bash
      sudo pacman -S gnome-keyring   # Arch-based
      ```
    - **Bazzite and similar handheld/console distros**: sign in from **Desktop Mode**, not **Gaming Mode** — Gaming Mode's console-style session doesn't reliably support the keyring, which is a known limitation of that mode, not an SGI bug

    Already installed but still failing? It's likely locked or not running for your current session, rather than missing:

    - **GNOME**: open **Passwords and Keys** from your app menu. If the "Login" keyring shows a lock icon, click it and unlock with your password
    - **KDE Plasma**: open **KWallet Manager** (search "wallet" in your app menu) and unlock your wallet
    - **Auto-login users** (no password at your login screen): your keyring can't auto-unlock without a login password to unlock it with, so it stays locked every session. Unlock it manually as above each time, or open your keyring/wallet app and set it to use a blank password so it unlocks automatically
    - **Minimal desktops/tiling window managers**: if you just installed `gnome-keyring`, it still won't be running until your next login (or your session's autostart config is set up) — log out and back in, or start it once with `gnome-keyring-daemon --start --components=secrets` before relaunching SGI
  </Accordion>

  <Accordion title="Where does SGI store its data on Linux?" id="linux-data-location">
    `~/.local/share/com.zevnda.steam-game-idler` — the equivalent of Windows' `%appdata%\com.zevnda.steam-game-idler\` referenced elsewhere on this page. The log file and settings file live there too, same structure as Windows.
  </Accordion>
</Accordions>

## Getting Help

<Callout type="info">
    Most errors show plain text like the ones quoted throughout this page. If you instead see a generic message like `Something went wrong... (some_error_code)` with a code that isn't mentioned anywhere on this page, it's likely an edge case SGI didn't anticipate rather than something you can fix yourself — please report it (include the code) rather than searching for a workaround
</Callout>

If these troubleshooting steps don't solve your issue:

1. **Check the [FAQ](/docs/faq)** for additional solutions
2. **Search existing issues** on the [GitHub repository](https://github.com/zevnda/steam-game-idler/issues)
3. **Create a new issue** with:
   - Detailed description of the problem
   - Steps to reproduce
   - Your system information (OS/version, Steam version)
   - Which sign-in method you're using (Steam Sign-in or Legacy Sign-in)
   - Relevant log file excerpts
   - Screenshots if applicable

<Callout type="info">
    When reporting issues, never share your Steam credentials or personal information
</Callout>
